الجزء الأول — تقرير المشروع كاملًا
================================================================================

الاسم
    ALJWHARAH ONE  |  الجوهرة ون

التعريف بجملة
    نظام تشغيل وكلاء محكوم، محلي-أول، مستقل عن أي نموذج سحابي.
    ليس محرر أكواد، وليس دردشة فوق مستودع.

الجملة التي تبيع المنتج
    كل ما فعله الوكيل قابل للإثبات والإعادة والرفض.
    ليست «الجوهرة تحكم» هي البيع. هذا هو الخندق.

العقل التنظيمي
    AJ Commander المحلي هو الحاكم.
    النماذج (Grok, Claude, GPT, Llama, aj-local) محركات قابلة للتبديل فقط.
    Grok مزوّد. ليس الدماغ.

وضعا التشغيل
    ONE   تنفيذ ذاتي موجّه للنتيجة. هذا هو الافتراضي.
    WORK  غرفة حرب حية متعددة وكلاء حقيقيين يناقشون ويعترضون ويجرّبون ويثبتون.
          ليس شاتًا محاكى. كل أخصائي ظاهر = وكيل زمن تشغيل حقيقي:
          هوية، دور، هدف، عقد، صلاحيات، سياق، أدوات، ميزانية، دورة حياة،
          نبض، مخرجات، حالة فشل، بيئة تنفيذ.


--------------------------------------------------------------------------------
ما الذي يراه المستخدم
--------------------------------------------------------------------------------

محطة عمل وكلاء واحدة. ليست IDE ثقيلًا وليست دردشة فقيرة.

    مهام  |  محادثة / ملحن  |  وكلاء ومخرجات
    محرر خفيف | طرفية | متصفح | حاسوب | فرق | مشاكل | سجلات

الملحن يدعم مرفقات وإشارات كيانات ومواصفات قبل المهام الكبيرة.
الصلاحيات دقيقة: لكل وكيل، أداة، مسار، نطاق، سر، فعل.
يمكن فرع البيئة، مقارنة حلول متوازية، واستعادة نقطة تحقق.


--------------------------------------------------------------------------------
النواة المعمارية
--------------------------------------------------------------------------------

    مستخدم
      → ملحن / CLI / عدسة المحرر   (عملاء رفيعون فقط)
        → ajd الحاكم المحلي
          → سياسة + عقود + ميزانية + ثقة متدرجة
            → وكلاء داخليون / سرب / ACP / مرتزقة
              → سجن OverlayFS / طرفية / متصفح
                → مدقّق حتمي مستقل
                  → دفتر أحداث ذري + حزمة تدقيق موقّعة

قواعد لا تُكسر
    1. الطفل لا يتجاوز صلاحية الأب.
    2. الوكيل الخارجي لا يختم المهمة أبدًا (cannotCertify).
    3. المحتوى منخفض الثقة (متصفح / webhook / مرتزق ≤ 0.35) بيانات فقط.
       لا يُشتق منه أمر أداة.
    4. الأسرار: تأجير محدود → استخدام → انتهاء أو سحب.
       ليست سرًا خامًا إلى الأبد.
    5. الدفتر للإلحاق فقط. لا حذف للأحداث الفاشلة. الفرع الفاشل يُعلَّم مجهضًا.


--------------------------------------------------------------------------------
المكدس التقني
--------------------------------------------------------------------------------

    الواجهة     React 19 + TypeScript + Vite + TanStack + Tailwind
    النواة      ajd محلي (TypeScript)
    العزل       Linux namespaces + chroot + prlimit + OverlayFS
                + setpriv --no-new-privs
    الدفتر      JSONL + fsync + كتابة ذرية + كاتب IPC مستقل + heal عند البتر
    الأسرار     AES-256-GCM
                المفتاح: /dev/shm أو AJ_MASTER_KEY (CI) أو DPAPI على ويندوز
                ممنوع أن يعيش المفتاح بجانب ملف الخزنة
    النماذج     aj-local + موصلات OpenAI / Anthropic / Grok عند وجود سر مختوم
    الأصل       مضيف Rust (Tauri / WebView2) بلا Electron
    الواجهات    CLI باسم aj / ajd   + عدسة JSON-RPC للمحرر


--------------------------------------------------------------------------------
ما يعمل فعليًا وليس شكلًا
--------------------------------------------------------------------------------

    وسيط أسرار بتأجير زمني وKMS HMAC دون إخراج القيمة، مع مسح Buffer
    ذكاء رموز: definitions + references + rename impact + diagnostics
    وكيل ACP خارجي تحت سلطة AJ: بيان قدرات، منح، ميزانية، نبض، سياسة أدوات
    دخول GitHub/CI عبر بوابة سياسة (HMAC، نافذة زمنية، منع التكرار)
    اقتصاد مهمة + تفاوض تمديد مرة واحدة عند استهلاك 90٪
    فهرس دلالي محلي 64-بعد للمستودع + حقن تبعيات عكسية عند التعديل
    استرجاع ذاتي للوكيل (rewind.self) بحد 3 وحماية نية المستخدم
    سرب محكوم بتصويت JSON وإجماع وجدار دمج
    مرتزقة: مقتطف داخل، رد ملوّث، ممنوع الكتابة والختم والأسرار
    شفاء دفتر بعد قتل منتصف الكتابة + كنس سجون يتيمة
    حارس بناء يقترح إصلاحًا داخل السجن ولا يدمج بلا نقرة واحدة

--------------------------------------------------------------------------------
الحدود الصادقة الدائمة
--------------------------------------------------------------------------------

    مثبت NSIS/MSIX الكامل يحتاج ويندوز + WebView2. هذا المضيف لينكس للبناء.
    Firecracker مسار عند توفر KVM وجذر. الافتراضي سجن namespaces + OverlayFS.
    المتجهات محلية مهشّرة 64-بعدًا. ليست OpenAI Embeddings ولا Chroma/Qdrant.
    سلاسل JavaScript في ترويسة Authorization لا تُمسح في V8.
    المسح الحقيقي على Buffer فقط.
    لا ندّعي 100٪ وقت تشغيل. ندّعي اتساق الحالة بعد الانهيار.
    Postgres ومزامنة الفرق مؤجّلان عمدًا ما دام الدفتر المحلي يعيد البناء.

الدفعة 1 من 10
الأساس والنواة المحكومة
--------------------------------------------------------------------------------

المشكلة
    منتج بلا هوية تشغيل وبلا فصل بين القائد والمنفّذ والمدقّق.

ما دخل
    وضع ONE الافتراضي
    كيان المهمة والعقد والوكيل
    سياسة أدوات بقائمة سماح. لا bash -lc مفتوح
    مدقّق حتمي أولًا (اختبارات، أنواع، ثوابت الفرق)
    قاضي على نموذج مختلف عن المنفّذ
    دفتر أحداث يعيد بناء المهمة بعد إعادة التشغيل
    النماذج مزوّدات. AJ هو العقل

الحد الصادق وقتها
    العزل كان منطقيًا (worktrees داخل العملية) قبل كسر وهم الصندوق الرملي

الدفعة 2 من 10
الثماني ثغرات الأمنية (Hardening-8)
--------------------------------------------------------------------------------

الثغرة                          العلاج الذي دخل
-----------------------------------------------------------------------
وهم العزل                       namespaces + chroot + سجن يُنسخ ويُدمَّر
bash -lc + قائمة منع            قائمة سماح أوامر + prlimit
مفتاح الخزنة في مجلد            /dev/shm أو AJ_MASTER_KEY
                                ممنوع بجانب ملف الخزنة
أسرار في ذاكرة العملية          نمط KMS: HMAC أو حقن env
                                العملية لا ترى القيمة
استقلال المدقّق غير مضمون       حتمي أولًا + نموذج مختلف
                                المدقّق لا يرى تفكير المنفّذ
حقن أوامر عبر متصفح/webhook     كائن سياق ملوّث + تثبيت تعريفات MCP
ACP يقرأ وله شبكة               لا خروج شبكي للابن
دفتر يُبتر عند القتل            fsync + كتابة ذرية + استئناف idempotent

اختُبر
    تهريب سجن، تشويش سياسة، قتل عشوائي أثناء كتابة الدفتر

الدفعة 3 من 10
ست إضافات منصّة
--------------------------------------------------------------------------------

    1. سجن تدميري / مسار MicroVM
       نسخة مؤقتة → تشغيل → تدمير. OverlayFS عند السماح.
       الضيف لا يحذف ملفات المضيف.

    2. اقتصاد الوكلاء
       رصيد رموز ومال لكل مهمة.
       عند الاستنزاف: وفّر أو اسأل بشرًا أو أوقف.

    3. ذاكرة متجهة محلية
       JSONL + تضمين مهشور 64-بعد + جيب تمام.
       بلا Chroma وبلا Qdrant.

    4. هيكل Tauri + Rust
       مضيف أصلي خفيف. بلا Electron.
       المعاينة تبقى ويبًا حتى يُجمَّع المثبت.

    5. Open Agent Protocol
       عقود مفتوحة. كل وكيل خارجي عامل.
       لا يملك الختم.

    6. شجرة مهام تشفي نفسها
       فشل المدقّق → فرع Resolution حتى 3 مرات ثم بشر.

الدفعة 4 من 10
الحوكمة القابلة للإثبات
--------------------------------------------------------------------------------

    حزمة تدقيق قابلة للتصدير
        مهمة + خطة + أدلة + حكم المدقّق + الأدوات + مراجع أسرار فقط
        لا قيم أسرار داخل الملف

    توقيع Ed25519 على الحزمة
        يثبت أن السجل لم يُعدَّل بعد التصدير

    مقاييس معلنة
        التقاط المدقّق، PASS كاذب، تراجع بعد الدمج،
        تكلفة المهمة الناجحة، زمن أول تدخل بشري

    ثقة متدرجة على كل كائن سياق
        مستخدم 1.00
        مستودع 0.75
        وكيل 0.55
        متصفح / webhook ≤ 0.35
        تحت 0.70 لا يُشتق أمر أداة

    تآكل ثقة ديناميكي
        مستودع موثوق يجلب حزمة npm أو HTTP
        فيهبط ذلك الجزء إلى ثقة المصدر المجلوب

    سمعة سلبية
        ليست رقمًا واحدًا مثل 92
        يُسجَّل نوع الفشل حتى يتجنّب القائد صنف مهمة لوكيل بعينه

    تشغيل جاف + ماذا لو
        يسجّل would-allow / would-deny دون تنفيذ
        ويقترح خلية السياسة المطلوبة للسماح

الدفعة 5 من 10
Epic 1 — آلة تفاوض الموارد
--------------------------------------------------------------------------------

المشكلة
    عند 90٪ من الميزانية كان القائد يوقف أو ينتظر بشرًا.
    مهام كادت تنتهي كانت تُهدر.

ما دخل
    مسار RenegotiateBudget
    المنفّذ يرسل طلبًا موثّقًا بالدليل
    aj-local يحكم مرة واحدة:
        يمنح تمديد 15٪   أو   يرفض وينهي المهمة

شروط المنح
    نسبة إنجاز الشجرة ≥ 50٪
    لا تمديد سابق لنفس المهمة
    سمعة الرفض/التراجع غير كارثية

حدود
    الأسرار تُمحى من نص الطلب
    التفاوض لا يرفع صلاحيات
    مرة واحدة فقط

الدفعة 6 من 10
Epic 2 — الذاكرة الدلالية الممتدة للمستودع
--------------------------------------------------------------------------------

المشكلة
    الوكيل يعدّل ملفًا فيكسر عشرة ملفات تستدعيه.
    لا يفهم روح مشروع جديد ضخم.

ما دخل
    خدمة WorkspaceIndexer في الخلفية
    لا توقف القائد (setImmediate)
    تستخرج الدوال والواجهات عبر محرك LSP الموجود أصلًا
    فهرس متجه محلي 64-بعد + استيرادات عكسية

عند تعديل ملف
    يُحقن مقتطف قصير مثل:
    «دالة calculateTotal في totals.ts يستدعيها InvoiceManager.ts.
     لا تكسر التوقيع.»

حدود
    الفهرس محلي في الذاكرة أو JSONL خفيف
    بلا OpenAI Embeddings وبلا Chroma/Qdrant
    التنبيه بيانات فقط (WorkspaceContextInjected)
    لا يمنح كتابة ولا يرفع صلاحيات
    قصّ المستودع الضخم عند 200 ملف لكل مسح

الدفعة 7 من 10
Epic 3 — الاسترجاع الذاتي للوكيل (Time-Travel)
--------------------------------------------------------------------------------

المشكلة
    rewindToSeq كانت يدوية للمشغّل البشري.
    الوكيل إذا خرّب البيئة يبقى على المسار الخاطئ.

ما دخل
    أداة rewind.self
        target_seq    رقم الحدث المطلوب
        reason        سبب التراجع في السجل الجنائي

    القائد يوقف المسار الحالي
    يستعيد لقطة السجن
    يفرّع الشجرة من ذلك الرقم
    المسار القديم يُعلَّم BranchPruned
    لا يُحذف أي حدث من الدفتر

    يُحقن في السياق:
    «عدت بالزمن لأن مسارك السابق فشل بسبب: [السبب]. لا تكرر الخطوات.»

حدود حديدية
    ممنوع الرجوع إلى ما قبل seq 1
    ممنوع إلغاء نية المستخدم (MissionCreated)
    حد أقصى 3 رجوعات لكل مهمة ثم WAITING_APPROVAL
    ACP والباحث لا يستدعيان الأداة
    حزمة التدقيق تسجّل كل رجوع وسببه


--------------------------------------------------------------------------------
الدفعة 8 من 10
Epic 4 — السرب المحكوم وغرفة الحرب
--------------------------------------------------------------------------------

المشكلة
    مسار خطي: وكيل واحد ثم قاضٍ واحد.
    لا توافق، ولا جدار دمج عند النزاع.

ما دخل
    القائد يفرّع وكلاء متوازيين بمحركات مختلفة
        مثال: Claude يكتب، GPT يراجع أمنًا، aj-local يكتب اختبارات

    محرك إجماع
        COMPLETE والدمج لا يتمّان إلا بأغلبية أو إجماع المراجعين

    جدار حل النزاع
        إذا اعترض المختبر على كود المبرمج
        تُفتح جلسة تسوية
        الدمج يُغلق حتى تُحل

قاعدة حديدية
    ممنوع الشات الحر بين الوكلاء.
    التواصل JSON فقط في الدفتر:
        proposal
        objection
        evidence
        approval

    حتى لو قال المدقّق PASS، لا تُختم المهمة إن وُجد سرب بلا إجماع.

الدفعة 9 من 10
Epic 5 + Epic 6 — المرتزقة + الفوضى والشفاء
--------------------------------------------------------------------------------

Epic 5 — وكلاء مرتزقة على الشبكة
    قناة مؤمّنة بـ HMAC (النقل المقصود WSS / mTLS)
    الوكيل الخارجي لا يرى مساحة العمل
    القائد يرسل مقتطفًا ويستقبل حمولة

    كل رد يُوسم tainted وثقته 0.15
    cannotCertify = true حرفيًا ومطلقًا
    ممنوع: fs.write، دمج، طرفية، أسرار، rewind، تعديل سياسة
    مقتطف فيه مفتاح أو Bearer يُرفض قبل أن يخرج

Epic 6 — هندسة فوضى واستئناف ميت
    قتل عملية أثناء سطر دفتر ناقص
        healLedger يسقط السطر المبتور
        الحالة تُعاد من آخر seq سليم

    عند إقلاع ajd
        يقرأ الدفتر أولًا
        إن وُجدت مهمة بلا ختم PASS/FAIL
            يُكنس السجن القديم
            يُبنى سجن جديد
            تُستأنف من آخر رقم ذري سليم

    لا نبيع 100٪ وقت تشغيل.
    نبيع 100٪ اتساق حالة.
    لا ملف يتيم ولا حالة معلّقة على المضيف بعد الاستئناف.

الدفعة 10 من 10
Epic 7 + 8 + 9 + 10 — الأصل والحراسة وواجهة المطوّر
--------------------------------------------------------------------------------

Epic 7 — محرك ويندوز الأصلي (Tauri)
    مضيف Rust. بلا Electron. WebView2 على ويندوز.
    IPC بين React وRust ملوّث:
        قائمة أوامر مسموحة فقط
        رفض المسارات (..)
        رفض مفتاح خام قادم من الواجهة
    نافذة بلا إطار
    صينية نظام: الحالة، فتح القائد، إيقاف فوري
    اختصار منطقي: Ctrl+Shift+Space
    إعداد حزمة NSIS / MSI في tauri.conf.json

Epic 8 — خزنة نظام أصلية
    ترتيب المفتاح الرئيسي:
        1. AJ_MASTER_KEY في CI
        2. Windows DPAPI / Credential Manager على ويندوز
        3. Linux Secret Service / secret-tool إن وُجد
        4. /dev/shm
    ممنوع ملف مفتاح بجانب الخزنة
    المسح: randomFill ثم أصفار على Buffer
    لا نص واضح في سجلات ويندوز

Epic 9 — وضع الحراسة الاستباقي
    يراقب فشل البناء والاختبار في الخلفية
    عند SyntaxError أو Failed Tests
        يفتح سجن OverlayFS ويجرّب إصلاحًا
    إن نجح داخل السجن يظهر إشعار:
        «الجوهرة رصدت خطأ في [الملف] وقامت بتجهيز حل مجرب بنجاح.
         انقر للمراجعة والدمج»
    ممنوع دمج أي كود في مستودع المضيف بلا نقرة موافقة صريحة

Epic 10 — CLI وعدسة الجوهرة
    aj init [مجلد]     يربط أي مجلد بالنواة ويفهرسه
    aj run "المهمة"    يشغّل عبر نفس ajd. لا زمن تشغيل ثانٍ
    عدسة JSON-RPC للمحرر:
        ping
        missions.list
        mission.diff
        jail.status
    الواجهات الخارجية عارض ومتحكّم رفيع فقط
    الحكم والعزل يبقيان داخل ajd

    إضافة VS Code منشورة في السوق
        البروتوكول جاهز. الإضافة نفسها ليست في المتجر
    BPF seccomp كامل
        الموجود: setpriv --no-new-privs
    Firecracker يقلع جذرًا كاملًا بلا صورة نواة وrootfs مُجهَّزة
    مسح سلاسل V8 بعد Authorization: Bearer
    Postgres ومزامنة أجهزة متعددة وفرق
        مؤجّل عمدًا. الدفتر المحلي يكفي لإعادة البناء بعد إعادة التشغيل
