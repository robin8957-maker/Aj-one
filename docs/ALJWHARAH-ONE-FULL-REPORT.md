# ALJWHARAH ONE — التقرير الكامل
## نظام تشغيل وكلاء محكوم · محلي-أول · كل فعل قابل للإثبات والإعادة والرفض

**الإصدار المعماري:** catalogRev 16  
**الشكل:** محطة عمل وكلاء (Agent Workstation) بوضعَين: ONE (تنفيذ ذاتي للنتيجة) و WORK (غرفة حرب متعددة الوكلاء).  
**العقل:** AJ Commander محلي. النماذج مزوّدات قابلة للتبديل وليست الدماغ.  
**الخندق:** ليست «الجوهرة تحكم» هي البيع. البيع هو: **كل ما فعله الوكيل قابل للإثبات والإعادة والرفض.**

---

# الجزء الأول — تقرير المشروع الكامل

## 1. ما هو المنتج

ALJWHARAH ONE ليس محرر أكواد ولا دردشة فوق مستودع. هو **نظام تشغيل وكلاء (Agent OS)** يضع فوق كل نموذج ووكيل خارجي:

- قائد (Commander) بسياسة وصلاحيات
- عقد لكل وكيل (هوية، دور، هدف، ميزانية، نبض، أدوات، بيئة)
- عزل تدميري للتنفيذ (namespaces + OverlayFS + سجن يُدمَّر بعد الاستدعاء)
- مدقّق مستقل لا يرى تفكير المنفّذ ولا يصدّق نفسه
- دفتر أحداث ذري قابل لإعادة البناء بعد الانهيار
- أسرار مُؤجَّرة بزمن وصلاحية — ليست مفاتيح أبدية في السياق

المنافسون (Cursor Cloud Agents، Antigravity، Devin، Kiro) يقدّمون وكلاء وأجهزة وArtifacts. تمايز الجوهرة أن هذه الأشياء تظهر في سطح واحد **تحت قائد وصلاحيات ومهام وسجون قابلة للمشاهدة والفرع والاسترجاع**.

## 2. وضعا التشغيل

| الوضع | المعنى |
|---|---|
| **ONE** | تنفيذ ذاتي موجَّه للنتيجة. الافتراضي. |
| **WORK** | غرفة حرب حية: وكلاء حقيقيون يناقشون ويعترضون ويجرّبون ويُثبِتون. ليس شاتًا مُحاكى. |

التبديل يغيّر سلوك التشغيل لا الشكل فقط.

## 3. السطح (Workstation)

محطة واحدة وليست IDE ثقيلًا ولا دردشة فقيرة:

- مهام · محادثة/ملحن · وكلاء/مخرجات
- محرر خفيف · طرفية PTY · متصفح · حاسوب · فرق · مشاكل · سجلات
- ملحن قوي: مرفقات، إشارات كيانات، مواصفات قبل المهام الكبيرة
- صلاحيات دقيقة لكل وكيل/أداة/مسار/نطاق/سر/فعل
- لقطات بيئة وفرع · ساحة حلول متوازية · تحقق خصمي

## 4. النواة المعمارية

```
مستخدم
  → ملحن / CLI / عدسة VS Code (عملاء رفيعون)
    → ajd (الحاكم المحلي)
      → سياسة + عقود + ميزانية + ثقة متدرجة
        → وكلاء داخليون / سرب / ACP / مرتزقة خارجيون
          → سجن OverlayFS / طرفية / متصفح
            → مدقّق حتمي مستقل
              → دفتر أحداث ذري + حزمة تدقيق موقَّعة
```

قواعد لا تُكسر:

1. الطفل لا يتجاوز صلاحية الأب.
2. الوكيل الخارجي **لا يختم المهمة** (`cannotCertify`).
3. المحتوى منخفض الثقة (متصفح / webhook / مرتزق ≤ 0.35) بيانات فقط — لا يشتق أوامر أدوات.
4. الأسرار: تأجير محدود → استخدام → انتهاء/سحب. ليست «سر خام إلى الأبد».
5. الدفتر للإلحاق فقط. لا حذف للأحداث الفاشلة. الفرع يُعلَّم مجهضًا.

## 5. المكدس

- الواجهة: React 19 + TypeScript + Vite + TanStack + Tailwind
- النواة: `ajd` محلي (TypeScript)
- العزل: Linux namespaces + chroot + prlimit + OverlayFS + setpriv --no-new-privs
- الدفتر: JSONL + fsync + كتابة ذرية + كاتب IPC مستقل + heal عند البتر
- الأسرار: AES-256-GCM + مفتاح في /dev/shm أو AJ_MASTER_KEY (CI) + مسار DPAPI لويندوز
- النماذج: aj-local + موصلات OpenAI/Anthropic/Grok عند وجود سر مختوم. Grok مزوّد لا دماغ.
- الأصل: مضيف Rust (Tauri/WebView2، بلا Electron) + CLI `aj`/`ajd`

## 6. ما يعمل فعليًا (وليس واجهة وهمية)

- وسيط أسرار: تأجير، KMS HMAC دون إخراج القيمة، مسح Buffer
- ذكاء رموز: definitions / references / rename impact / diagnostics (ليس regex وحده)
- ACP خارجي تحت سلطة AJ: بيان قدرات، منح، ميزانية، نبض، سياسة أدوات
- دخول أحداث GitHub/CI عبر بوابة سياسة (HMAC، نافذة زمنية، منع التكرار)
- اقتصاد مهمة + تفاوض تمديد مرة واحدة عند 90٪
- فهرس دلالي محلي 64-بعد للمستودع + حقن تبعيات عكسية عند التعديل
- استرجاع ذاتي للوكيل (`rewind.self`) بحد 3 وحماية نية المستخدم
- سرب محكوم بتصويت JSON وإجماع وجدار دمج
- مرتزقة: مقتطف داخل، رد ملوَّث، ممنوع الكتابة/الختم/الأسرار
- شفاء ذاتي للدفتر بعد قتل منتصف الكتابة + كنس سجون يتيمة
- حارس بناء يقترح إصلاحًا في السجن ولا يدمج بلا نقرة

## 7. الاختبارات

حزمة `npm test` تشمل — من بين أخرى:

`runtime` · `v2-engines` · `v3-governed` · `v4-hardening` · `workstation` · `work` · `connections` · `sandbox` · `hardening-8` · `os-next` · `platform-6` · `governance` · `hardening-next` · `negotiate` · `indexer` · `rewind-self` · `phase5` · `phase6`

إضافة: اختبارات Rust للمضيف الأصلي (IPC، اختصار، صينية، مسح مفتاح).

## 8. الحدود الصادقة الدائمة

- هذا المضيف لينكس للبناء/المعاينة. مثبت NSIS/MSIX الكامل يحتاج ويندوز + WebView2.
- Firecracker موجود كمسار عند توفر KVM+جذر؛ الافتراضي سجن namespaces + OverlayFS.
- المتجهات محلية مُهشَّرة 64-بعدًا — ليست نموذج تضمين سحابي ولا Chroma/Qdrant.
- سلاسل JavaScript للأسرار في ترويسة HTTP لا تُمسح في V8؛ المسح الحقيقي على Buffer.
- لا ندّعي 100٪ uptime. ندّعي **اتساق الحالة** بعد الانهيار.

# الجزء الثاني — التعديلات الأخيرة: المراحل العشر

ترتيبها الزمني والمعماري كما بُنيت. كل مرحلة اختُبرت قبل الانتقال.

==================================================
## المرحلة 0 — الأساس والنواة المحكومة
==================================================

**المشكلة:** منتج بلا هوية تشغيل، وبلا فصل بين القائد والمنفّذ والمدقّق.

**ما أُنجز:**

- وضع ONE الافتراضي + كيان المهام والعقود والوكلاء
- سياسة أدوات: قائمة سماح أوامر، لا `bash -lc` مفتوح
- مدقّق حتمي أولًا (اختبارات، أنواع، ثوابت الفرق) + مسار نموذج مختلف للقاضي
- دفتر أحداث يعيد بناء المهمة بعد إعادة التشغيل
- Grok وغيره **مزوّدات** فقط. AJ الحاكم المحلي هو العقل التنظيمي

**الحد الصادق:** العزل كان منطقيًا في البداية (worktrees داخل العملية) قبل تصليح وهم الصندوق الرملي.

==================================================
## المرحلة 1 — الثمانِي ثغرات (Hardening-8)
==================================================

| الثغرة | لماذا خطرة | العلاج الذي دخل |
|---|---|---|
| وهم العزل | كود خبيث يكسر المضيف | namespaces + chroot + سجن يُنسخ ويُدمَّر |
| `bash -lc` + قائمة منع | التفافية base64/مفسّرات | قائمة **سماح** + prlimit |
| مفتاح الخزنة في مجلد | أضعف حلقة AES-GCM | مفتاح في /dev/shm أو AJ_MASTER_KEY — ممنوع بجانب الخزنة |
| الأسرار في ذاكرة العملية | سلاسل JS تبقى | نمط KMS: HMAC/حقن env دون إرجاع القيمة |
| استقلال المدقّق | نفس السياق = PASS طقسي | حتمي أولًا + نموذج مختلف + لا رؤية لتفكير المنفّذ |
| حقن أوامر عبر متصفح/webhook | تسميم أدوات | كائن سياق ملوَّث + تثبيت تعريفات MCP |
| ACP يقرأ + شبكة | قناة تسريب | لا خروج شبكي للابن أو عبر بروكسي |
| دفتر يُبتر عند القتل | حالة غير قابلة للاسترجاع | fsync + كتابة ذرية + إعادة تشغيل idempotent |

**اختبارات:** تهريب سجن، تشويش سياسة، قتل عشوائي للدفتر.

==================================================
## المرحلة 2 — ست إضافات منصّة
==================================================

1. **MicroVM / سجن تدميري:** نسخة مؤقتة → تشغيل → تدمير. المضيف لا يُحذف من الضيف. OverlayFS عند السماح (نسخ عند الكتابة).
2. **اقتصاد الوكلاء:** رصيد رموز/مال. عند الاستنزاف: توفير / اسأل بشرًا / أوقف.
3. **ذاكرة متجهة محلية:** JSONL + تضمين مهشور 64-بعد + جيب تمام. بلا Chroma/Qdrant.
4. **هيكل Tauri+Rust:** مضيف أصلي خفيف. المعاينة تبقى الويب حتى يُجمَّع المثبت.
5. **Open Agent Protocol:** عقود مفتوحة؛ كل وكيل خارجي عامل. لا يختم.
6. **DAG شفاء ذاتي:** فشل المدقّق → فرع Resolution حتى 3 مرات ثم بشر.

==================================================
## المرحلة 3 — الحوكمة القابلة للإثبات
==================================================

- **حزمة تدقيق قابلة للتصدير:** مهمة + خطة + أدلة + حكم + أدوات + مراجع أسرار فقط (لا قيم)
- **توقيع Ed25519** على الحزمة
- **مقاييس:** التقاط المدقّق، PASS كاذب، تراجع، تكلفة، زمن أول تدخل بشري
- **ثقة متدرجة:** مستخدم 1.0 · مستودع 0.75 · وكيل 0.55 · متصفح/webhook ≤ 0.35
- **تآكل ثقة ديناميكي:** مستودع يجلب npm/HTTP يهبط إلى مستوى المصدر الملوَّث
- **سمعة سلبية:** ليس رقمًا واحدًا؛ يُسجَّل *نوع* الفشل
- **تشغيل جاف + What-If:** يسجّل would-allow / would-deny ويقترح خلية السياسة دون تنفيذ

**الجملة الثابتة:** كل ما فعله الوكيل قابل للإثبات والإعادة والرفض.

==================================================
## المرحلة 4 — الوعي الاستباقي والتفاوض (Epics 1–3)
==================================================

### Epic 1 — آلة تفاوض الموارد
عند استهلاك **90٪** لا يوقف القائد ولا يوقظ بشرًا فورًا.  
المنفّذ يطلب · **aj-local** يحكم · تمديد **15٪ مرة واحدة** أو إنهاء المهمة.

قواعد المنح: DAG ≥ 50٪ مكتمل، لا تمديد سابق، سمعة رفض/تراجع غير كارثية.  
الأسرار تُمحى من سبب الطلب. لا رفع صلاحيات.

### Epic 2 — ذاكرة دلالية ممتدة للمستودع
`WorkspaceIndexer` في الخلفية (`setImmediate` لا يوقف القائد):

- استخراج دوال/واجهات عبر محرك LSP الموجود
- فهرس متجه محلي + استيرادات **عكسية**
- عند `fs.write`: حقن مقتطف  
  «`calculateTotal` في totals.ts يستدعيه InvoiceManager.ts — لا تكسر التوقيع»
- التنبيه بيانات (`WorkspaceContextInjected`) — لا يمنح كتابة

### Epic 3 — استرجاع ذاتي للوكيل
أداة `rewind.self` (`target_seq`, `reason`):

- الدفتر للإلحاق فقط؛ المسار الفاشل `BranchPruned`
- استعادة لقطة السجن
- حقن: «عدت بالزمن لأن المسار السابق فشل: [سبب]. لا تكرر الخطوات»
- ممنوع قبل seq 1 وقبل `MissionCreated`
- حد 3 لكل مهمة ثم `WAITING_APPROVAL`
- ACP لا يستدعي الأداة
- حزمة التدقيق تسجّل كل رجوع

==================================================
## المرحلة 5 — السرب والمرتزقة والفوضى (Epics 4–6)
==================================================

### Epic 4 — سرب محكوم (WORK 2.0)
وكلاء متوازون بمحركات مختلفة (مثلًا Claude يكتب، GPT يراجع أمنًا، aj-local يختبر).  
**ممنوع الشات الحر.** التواصل JSON في الدفتر فقط:

`proposal | objection | evidence | approval`

- إكمال المهمة ودمج الكود يحتاجان إجماع (أغلبية أو إجماع مراجعين)
- اعتراض المختبر على المبرمج → جلسة تسوية + جدار دمج
- حتى PASS المدقّق لا يختم المهمة إن وُجد سرب بلا إجماع

### Epic 5 — وكلاء مرتزقة (ACP شبكي)
- إطار مصادق بـHMAC (النقل المقصود WSS/mTLS)
- مقتطف سياقي فقط — لا مساحة عمل كاملة
- كل رد `tainted` وثقة **0.15**
- `cannotCertify: true` حرفيًا
- ممنوع: `fs.write` · دمج · طرفية · أسرار · rewind
- مقتطف فيه مفتاح يُرفض قبل الخروج

### Epic 6 — هندسة فوضى وشفاء النواة
- قتل عملية أثناء سطر دفتر ناقص → `healLedger` يسقط المبتور
- عند الإقلاع: إعادة بناء من الدفتر + كنس `/tmp/aj-microvm` و`aj-jail`
- لا نبيع 100٪ uptime. نبيع **100٪ اتساق حالة**

==================================================
## المرحلة 6 — الأصل وتجربة المطوّر (Epics 7–10)
==================================================

### Epic 7 — محرك ويندوز الأصلي (Tauri)
- مضيف Rust: بلا Electron، WebView2 على ويندوز
- IPC ملوَّث: قائمة أوامر، رفض المسارات، رفض مفتاح خام من الواجهة
- نافذة بلا إطار · صينية نظام (حالة / فتح / إيقاف فوري)
- اختصار عالمي منطقي: `Ctrl+Shift+Space`
- إعداد حزمة NSIS/MSI في `tauri.conf.json`

### Epic 8 — خزنة نظام أصلية
ترتيب المفتاح الرئيسي:

1. `AJ_MASTER_KEY` للـCI  
2. Windows DPAPI / Credential Manager (مسار الترجمة على ويندوز)  
3. Linux Secret Service / `secret-tool` إن وُجد  
4. /dev/shm — **ليس** ملفًا بجانب الخزنة  

المسح: `randomFill` ثم أصفار على Buffer.

### Epic 9 — وضع الحراسة
مراقبة فشل البناء/الاختبار → تجربة إصلاح داخل OverlayFS → إشعار:

> الجوهرة رصدت خطأ في [الملف] وقامت بتجهيز حل مجرب بنجاح. انقر للمراجعة والدمج

**يُمنع الدمج في مستودع المضيف بلا موافقة نقرة واحدة.**

### Epic 10 — CLI وعدسة الجوهرة
- `aj init [مجلد]` يربط أي مجلد بالنواة
- `aj run "المهمة"` يشغّل عبر **نفس** ajd (لا زمن تشغيل ثانٍ)
- JSON-RPC للعدسة: `ping` · `missions.list` · `mission.diff` · `jail.status`
- الواجهات الخارجية عارض/متحكم رفيع. الحكم والعزل يبقيان في ajd

## خريطة المراحل العشر في سطر واحد
==================================================

```
0 نواة محكومة
 → 1 عزل + KMS + دفتر ذري
 → 2 سجن تدميري + اقتصاد + متجه + Tauri + OAP + شفاء DAG
 → 3 تدقيق موقَّع + ثقة متدرجة + تشغيل جاف
 → 4 تفاوض ميزانية + فهرس مستودع + rewind.self
 → 5 سرب JSON + مرتزقة ملوَّثون + فوضى/استئناف
 → 6 ويندوز أصلي + خزنة نظام + حارس + CLI/عدسة
```

## ما لم يُدَّعَ بعد هذه المراحل
==================================================

- مثبت ويندوز موقَّع وجاهز للمتجر على مضيف لينكس هذا
- حلقة `RegisterHotKey` فوق كل تطبيقات ويندوز (المنطق مختبَر؛ الربط يحتاج نافذة أصلية حية)
- إضافة VS Code منشورة في السوق (البروتوكول جاهز)
- BPF seccomp كامل (الموجود: `setpriv --no-new-privs`)
- Firecracker يقلع جذرًا كاملًا بلا صورة نواة/rootfs مُجهَّزة
- مسح سلاسل V8 بعد `Authorization: Bearer`
- Postgres / مزامنة فرق — مؤجَّل عمدًا ما دام الدفتر المحلي يعيد البناء

## الجملة الختامية
==================================================

الجوهرة ليست أقوى لأنها تشغّل نماذج أكثر.  
هي أقوى لأن **الوكيل لا يصدّق نفسه، والسر لا يعيش للأبد، والدفتر لا يُكذَب عليه، والمهمة لا تُختم إلا بدليل يمكن رفضه.**

كل فعل قابل للإثبات، للإعادة، وللرفض.
